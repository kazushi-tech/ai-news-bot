## 概要 (TL;DR)

Hugging Faceは、MCP (Model Context Protocol) を活用し、わずか50行のTypeScriptコードで動作するシンプルなエージェント「Tiny Agents」を実装・公開しました。MCPはLLMにツールセットを公開するための標準APIであり、LLMのネイティブなツール呼び出しサポートと組み合わせることで、エージェントAIの開発を大幅に簡素化できることを示しています。MCPクライアントがあれば、エージェントは基本的にその上に構築された`while`ループに過ぎない、というシンプルさが強調されています。

## 重要ポイント

*   **MCP (Model Context Protocol) の定義**: LLMにツールセットを公開するための標準APIであり、シンプルながら強力です。
*   **エージェントの簡素化**: MCPクライアントがあれば、エージェントはLLM推論クライアントとツールセットを組み合わせた「単なる`while`ループ」として実装可能。
*   **コードの簡潔さ**: Hugging FaceのTypeScript SDK (`@huggingface/inference`) をベースに、わずか50行のコードでエージェントを実現。
*   **LLMのネイティブツール呼び出しサポート**: 最新のLLMが関数呼び出し（ツール利用）に特化して学習されていることが、この実装の基盤となっています。
*   **デモの提供**: `npx @huggingface/mcp-client` コマンドで簡単にデモを実行でき、ファイルシステムアクセスやWebブラウジングを行うエージェントを体験できます。
*   **デフォルト設定**: デモでは「Qwen/Qwen2.5-72B-Instruct」モデルと「Nebius」プロバイダーを使用。

## 詳細レポート（What happened/背景/影響/関係者/データ）

**What happened:**
Hugging Faceは、MCP (Model Context Protocol) を利用した「Tiny Agents」という、わずか50行のTypeScriptコードで記述されたエージェントを開発し、その実装方法をブログ記事で公開しました。このエージェントは、MCPサーバーから提供されるツールをLLMにフックし、ユーザーの指示に基づいてツールを呼び出し、タスクを遂行します。

**背景:**
近年、LLMは関数呼び出し（ツール利用）のネイティブサポートが進化しており、ツール名、説明、JSONSchema形式のパラメータでツールを定義し、LLMが適切に呼び出すことが可能になりました。MCPはこのツール呼び出し機能を標準化し、様々なツールをLLMに公開するためのプロトコルとして登場。Hugging Faceは、このMCPとLLMのツール呼び出し機能を組み合わせることで、エージェントの実装が極めてシンプルになることを実証しました。

**影響:**
このアプローチは、エージェントAIの開発を大幅に簡素化し、より多くの開発者が複雑なエージェントシステムを構築できるようになる可能性を秘めています。手動でプロンプトにツール記述を埋め込む必要がなくなり、LLMの`tools`フィールドを通じてツールを渡すだけで済むため、開発効率が向上します。

**関係者:**

*   **Hugging Face**: 記事の著者であり、`huggingface.js`モノリポ内の`mcp-client`サブパッケージとしてTiny Agentのコードを開発・公開。
*   **OpenAI**: LLMの関数呼び出しに関する事実上の標準を定義し、プロンプトガイドがTiny Agentのシステムプロンプトに影響を与えています。
*   **MCPコミュニティ**: Model Context Protocolの標準化とSDK開発に関わる人々。

## リスクと課題

*   **MCPサーバーのローカル性**: 現在、すべてのMCPサーバーはローカルプロセスとして動作しており、リモートサーバーのサポートは今後予定されています。
*   **モデルによるツール解析の必要性**: Gemma 3などの一部のモデルでは、ネイティブツールを使用していないため、ツール解析を独自に実装する必要がある場合があります。
*   **パフォーマンスのばらつき**: 各推論プロバイダーやモデルによって、関数呼び出しの最適化が異なるため、パフォーマンスにばらつきが生じる可能性があります。

## 今後の見通し/アクション

*   **モデルの実験**: Mistral-Small-3.1-24B-Instruct-2503 (関数呼び出しに最適化) や Gemma 3 27B (ツール解析の実装が必要な場合あり) など、様々なLLMでの実験。
*   **推論プロバイダーの実験**: Cerebras, Cohere, Fal, Fireworks, Hyperbolic, Nebius, Novita, Replicate, SambaNova, Togetherなど、多様な推論プロバイダーでのパフォーマンス検証。
*   **ローカルLLMとの連携**: `llama.cpp` や `LM Studio` を使用してローカルで動作するLLMとの連携を試みる。
*   **コミュニティ貢献**: 本プロジェクトはオープンソースであり、プルリクエストや貢献を歓迎しています。
