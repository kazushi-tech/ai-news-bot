## 概要 (TL;DR)

Hugging Faceは、アラビア語大規模言語モデル（LLM）の評価プラットフォーム「Open Arabic LLM Leaderboard (OALL)」の第2版をリリースしました。この新バージョンは、以前のリーダーボードが抱えていたリソース制限、結果の信頼性不足、機械翻訳されたタスクの不適切さ、ベンチマークの飽和といった課題に対処しています。v2では、ネイティブアラビア語の高品質なベンチマークを多数追加し、飽和したタスクや翻訳タスクを削除。さらに、UIの改善、チャットテンプレートの導入、モデル提出数の制限を設け、より客観的で、アラビア語の言語的・文化的ニュアンスを反映した評価を目指しています。

## 重要ポイント

*   **OALL v2のリリース**: アラビア語LLMの評価を目的とした「Open Arabic LLM Leaderboard」の第2版が公開されました。
*   **課題解決**: v1の課題（リソース、信頼性、翻訳タスクの不適切さ、ベンチマークの飽和）に対応し、より統一され、アクセスしやすく、透明性の高い評価プラットフォームを提供します。
*   **ネイティブベンチマーク重視**: ネイティブアラビア語の高品質なベンチマーク（Native Arabic MMLU, MedinaQA, AraTrust, ALRAGEなど）を多数追加し、アラビア語固有の複雑さを評価します。
*   **飽和・翻訳タスクの削除**: 飽和したベンチマークや機械翻訳されたタスクを削除し、評価の関連性と差別化能力を向上させました。
*   **ALRAGEの導入**: アラビア語のRetrieval Augmented Generation (RAG) 能力を評価する新しいベンチマーク「ALRAGE」を導入。LLM-as-judgeメトリックを使用し、高度な生成能力を評価します。
*   **UI/UX改善と提出制限**: UIの改善、チャットテンプレートの導入、組織ごとのモデル提出数制限（週5回）を導入し、公平な評価機会を確保しました。
*   **モデルランキングの変化**: v2ではモデルのランキングに変化が見られ、特にLlama3.3-70B-instructが多くのカテゴリでトップに浮上するなど、新たな評価基準が影響を与えています。

## 詳細レポート（What happened/背景/影響/関係者/データ）

**What happened:**
Hugging Faceは、2A2I、TII、SDAIA、King Salman Global Academy for Arabic Language、Inception、MBZUAI、Scale's SEALなどの協力のもと、Open Arabic LLM Leaderboard (OALL) の第2版をリリースしました。これは、アラビア語LLMの評価における既存の課題を解決し、より包括的で信頼性の高いプラットフォームを提供することを目的としています。

**背景:**
アラビア語をサポートするLLMの増加に伴い、専用の評価リーダーボードの必要性が高まっていました。しかし、従来のリーダーボードには以下の課題がありました。
*   **リソース制限**: コミュニティメンバーが評価に必要な計算リソースにアクセスできない。
*   **結果の信頼性**: 自己申告制の評価結果の正確性・真正性を保証するメカニズムがない。
*   **ベンチマークの不適切さ**: 英語からの翻訳タスクが多く、アラビア語の固有の複雑さ（文法、形態論、方言、文化的ニュアンス）を捉えきれていなかった。
*   **ベンチマークの飽和**: 一部のタスクでモデルがほぼ完璧なスコアを達成し、差別化能力が低下していた。
*   **バグ**: v1の主要タスクの一つであるAlGhafaにおいて、回答選択肢のチェック方法にバグがあり、特に小規模モデルのランキングに不公平な影響を与えていました。

**影響:**
OALL v2の導入により、アラビア語LLMのより正確で公平な評価が可能になります。ネイティブアラビア語タスクへのシフトは、モデルが実世界のアラビア語使用状況にどれだけ対応できるか、より明確な洞察を提供します。新しいベンチマーク（特にALRAGE）は、RAGのような高度な能力の評価を可能にし、モデル開発の方向性を示唆します。提出制限は、より多様な組織のモデルが評価される機会を増やし、公平性を促進します。モデルランキングに変化が生じ、特にLlama3.3-70B-instructが多くのカテゴリでトップに浮上するなど、新たな評価基準がモデルの相対的な強みに影響を与えています。

**関係者:**
*   **HuggingFace**: リーダーボードのホスティングと開発。
*   **2A2I, TII**: OALL v1の立ち上げに関与。TIIは評価バックエンドのインフラを提供。
*   **SDAIA, King Salman Global Academy for Arabic Language**: Balsam Indexを導入。
*   **Inception, MBZUAI**: AraGen Leaderboardを導入。MBZUAIは新しいネイティブベンチマーク（Native Arabic MMLU, MedinaQA, MMLU-HT）を提供。
*   **Scale's Safety, Evaluations, and Alignment Lab (SEAL)**: 多言語リーダーボードの一部としてアラビア語リーダーボードを公開。
*   **コミュニティ**: v1へのフィードバック、モデル提出、議論を通じて貢献。
*   **Argilla**: ALRAGEデータセットの人間による検証スプリントに協力。
*   **Qwen2.5-72B-Instruct**: ALRAGEベンチマークのLLM-as-judgeモデルとして使用。
*   **BAAI/bge-m3**: ALRAGEベンチマークでコンテキスト取得に使用される埋め込みモデル。

**データ:**
*   **OALL v1の活動**: 7ヶ月で46,000以上の訪問者、過去1ヶ月で2,000以上の訪問、100以上のいいね、8件のGoogle Scholar引用。700以上のモデルが提出され、180以上の組織が参加。
*   **モデルタイプとサイズ**: v1提出モデルの70%以上がチャット/ファインチューンモデル、11%が事前学習済みモデル。50%以上が7Bパラメータ未満。
*   **リーダーボードの比較**: OALLは韓国語、ポーランド語、ポルトガル語に次いで最も活発なリーダーボードの一つ。
*   **ベンチマークの変更**:
    *   **v1から維持**: AlGhafa (ネイティブアラビア語部分のみ), EXAMS, Belebele (アラビア語タスク)。
    *   **v2で追加**: Native Arabic MMLU (40タスク, 15,000問), Human Translated MMLU (MMLU-HT, 57タスク), MedinaQA, AraTrust (522問, 安全性・真実性), ALRAGE (RAG評価フレームワーク, 40冊のアラビア語書籍からデータ生成)。
*   **モデル提出制限**: 組織あたり週5回。
*   **パフォーマンス比較**: OALL v2ではLlama3.3-70B-instructが多くのカテゴリでトップに浮上。Qwenモデルも引き続き強力なベースラインとして機能。AceGPTとJaisファミリーでは、一般的に大規模モデルほどスコアが高い傾向にあるが、一部例外も確認された。v2の平均スコアはv1より高い傾向にあるが、7Bモデルでは例外あり（ALRAGEのような生成タスクが小規模モデルに不利なためと推測）。

**OALL v2で使用されるデータセットの概要**

| :------------------------- | :------------------------- |
| AlGhafa (6 tasks)          | Native Arabic MMLU (40 tasks) |
| EXAMS                      | Human Translated MMLU (57 tasks) |
| Belebele (2 tasks)         | MedinaQA                   |
|                            | AraTrust                   |
|                            | ALRAGE                     |

## リスクと課題

*   **ベンチマークの飽和**: モデルの性能向上に伴い、既存のベンチマークが飽和し、モデル間の差別化が難しくなる可能性が常に存在します。v2では飽和したタスクを削除しましたが、将来的に新たな飽和が発生する可能性があります。
*   **アラビア語の多様性への対応**: 複雑な文法、形態論、多様な方言、文化的ニュアンスを完全に捉えるベンチマークの継続的な開発が必要です。現在のベンチマークが全ての側面を網羅しているわけではありません。
*   **評価の網羅性**: 数学、推論、幻覚、特定のドメインなど、まだカバーされていない評価領域が存在し、これらに対するベンチマークの追加が求められます。
*   **LLM-as-judgeの限界**: ALRAGEで使用されるLLM-as-judgeメトリックは強力ですが、判断モデル自体のバイアスや限界が評価結果に影響を与える可能性があり、その信頼性を継続的に検証する必要があります。
*   **モデル提出の公平性**: 組織あたりの提出制限は公平性を高める一方で、評価待ちのキューや処理速度が新たな課題となる可能性もあります。
