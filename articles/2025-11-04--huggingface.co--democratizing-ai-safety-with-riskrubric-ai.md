## 概要 (TL;DR)
Hugging Faceは、AIモデルの安全性とセキュリティを標準化された方法で評価する新イニシアチブ「RiskRubric.ai」を発表しました。Cloud Security AllianceとNoma Securityが主導し、透明性、信頼性、セキュリティ、プライバシー、安全性、評判の6つの柱でモデルを評価し、リスクスコアとグレードを提供します。これにより、オープンモデルエコシステムにおける信頼構築と安全性向上が目指されます。

## 重要ポイント
*   AIモデルの安全性・セキュリティ評価を標準化し、民主化することを目的とした「RiskRubric.ai」が立ち上げられました。
*   RiskRubric.aiは、透明性、信頼性、セキュリティ、プライバシー、安全性、評判の6つの柱でモデルを評価します。
*   評価はNoma Securityの機能を利用して自動化され、1,000以上の信頼性テスト、200以上の敵対的セキュリティプローブ、コードスキャンなどが含まれます。
*   評価結果は0-100のスコアとA-Fのグレードで提供され、具体的な脆弱性、推奨される緩和策、改善提案も含まれます。
*   2025年9月時点の評価結果では、オープンモデルが特定の側面（特に透明性）でクローズドモデルを上回る場合があること、リスク分布が二極化していること、安全性がセキュリティと密接に関連していること、ガードレールが透明性を損なう可能性があることが判明しました。
*   標準化された公開評価は、コミュニティ全体のモデル安全性向上に貢献し、透明な改善の好循環を生み出すと期待されています。

## 詳細レポート
### What happened
Hugging Faceは、AIモデルの標準化されたリスク評価プラットフォーム「RiskRubric.ai」の立ち上げを発表しました。これは、AIモデルエコシステムにおける安全性とセキュリティの報告を加速させるための新しい取り組みです。

### 背景
Hugging Faceハブには50万以上のモデルが存在しますが、ユーザーがセキュリティ、プライバシー、潜在的な故障モードの観点から最適なモデルを選択・評価する体系的な方法が不足していました。AIモデルの能力向上と普及加速に伴い、AIの安全性とセキュリティに関する報告も同様に迅速な進歩が求められています。

### 影響
*   モデル全体で一貫性のある比較可能なリスクスコアを提供し、開発者が特定のニーズ（プライバシー、信頼性など）に基づいてモデルをフィルタリングし、デプロイメントの意思決定を支援します。
*   標準化された公開リスク評価により、コミュニティ全体がモデルの安全性向上に協力できる環境を構築します。
*   開発者はモデルの強化が必要な箇所を特定し、コミュニティは修正、パッチ、より安全なファインチューニング版を提供することで、透明な改善の好循環を促進します。

### データ
#### 評価方法
RiskRubric.aiは、以下の6つの柱でモデルを評価し、0-100のスコアとA-Fのレターグレードを提供します。Noma Securityの機能を利用して評価プロセスは自動化されています。

| 評価の柱 | 評価内容の例 |
| :------- | :----------- |
| **透明性** | ドキュメントレビュー（トレーニングデータ、メソッド） |
| **信頼性** | 1,000+のテスト（一貫性、エッジケース処理） |
| **セキュリティ** | 200+の敵対的プローブ（ジェイルブレイク、プロンプトインジェクション）、自動コードスキャン |
| **プライバシー** | データ保持、漏洩テスト |
| **安全性** | 構造化された有害コンテンツテスト |
| **評判** | (記事に具体的な評価内容は記載なし) |

各評価には、具体的な脆弱性、推奨される緩和策、改善提案も含まれます。

#### 2025年9月時点の評価結果の傾向
*   **オープンモデル vs クローズドモデル**: 特定のリスク次元（特に透明性）において、オープンモデルがクローズドモデルを上回る結果が見られました。オープンな開発実践が透明性に寄与しています。
*   **リスク分布の二極化**:
    *   総リスクスコアは47～94の範囲で、中央値は81（100点満点）。
    *   モデルの54%がAまたはBレベルの「より安全」な範囲に集中していますが、パフォーマンスの低いモデルの長い裾野が平均を押し下げています。
    *   50-67点（C/Dレベル）のモデルは「中程度から低い全体的な保護」を提供し、セキュリティギャップが懸念される領域です。
    *   **示唆**: 「平均的な」モデルが安全であると仮定すべきではありません。弱いモデルの存在が現実であり、攻撃者はそこに焦点を当てます。企業は最低しきい値（例：75点）を設定し、不適切なモデルが本番環境に投入されないようにすべきです。
*   **安全性リスクとセキュリティ姿勢の関連性**:
    *   安全性・社会性（有害出力防止）の柱はモデル間で最も大きなばらつきを示します。
    *   セキュリティ強化（プロンプトインジェクション防御、ポリシー適用）に投資するモデルは、安全性スコアも高い傾向にあります。
    *   **示唆**: コアセキュリティ制御の強化は、ジェイルブレイク防止だけでなく、下流の危害も直接的に軽減します。安全性は堅牢なセキュリティ姿勢の副産物である可能性が高いです。
*   **ガードレールと透明性のトレードオフ**:
    *   厳格な保護策（ガードレール）は、エンドユーザーに対するモデルの透明性を低下させる可能性があります（例：説明なしの拒否、隠された境界）。
    *   これにより、ユーザーはシステムが安全であっても「不透明」だと認識し、信頼のギャップが生じる可能性があります。
    *   **示唆**: セキュリティは信頼を犠牲にすべきではありません。強力な保護と説明的な拒否、出所情報、監査可能性を組み合わせることで、防御を緩めることなく透明性を維持できます。

## リスクと課題
*   **評価の複雑性**: 50万以上のAIモデルが存在する中で、セキュリティ、プライバシー、潜在的な故障モードを体系的に評価する方法が不足していました。
*   **「平均的な安全性」の誤解**: 多くのモデルが安全な範囲に集中する一方で、パフォーマンスの低いモデルの長い裾野が存在し、これらが攻撃の標的となるリスクがあります。
*   **透明性とセキュリティのトレードオフ**: 厳格なセキュリティ対策（ガードレール）がモデルの透明性を損ない、ユーザーの信頼を低下させる可能性があります。

## 今後の見通し/アクション
*   **コミュニティによる安全性向上**: 標準化された公開リスク評価により、開発者はモデルの強化が必要な箇所を特定し、コミュニティは修正、パッチ、より安全なファインチューニング版を提供することで、透明な改善の好循環が生まれます。
*   **学習と理解の深化**: コミュニティ全体が、最良のモデルを研究することで、安全性に関して何が機能し、何が機能しないかを理解できるようになります。
*   **参加の呼びかけ**: モデルを評価のために提出すること（または既存モデルを提案すること）、および評価方法とスコアリングフレームワークに関するフィードバックを提供することが推奨されています。
*   **企業のアクション**: 企業はRiskRubric.aiの複合スコアを利用して、調達やデプロイメントの最低しきい値（例：75点）を設定し、不適切なモデルが本番環境に投入されないようにすることが推奨されます。
