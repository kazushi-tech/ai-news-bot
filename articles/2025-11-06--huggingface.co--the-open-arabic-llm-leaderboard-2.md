## 概要 (TL;DR)
Open Arabic LLM Leaderboard (OALL) の第2版がリリースされました。本バージョンは、アラビア語LLMの評価における既存の課題（計算リソースの制限、結果の信頼性、ベンチマークの質）に対処し、より客観的で文化的に適切な評価を提供することを目的としています。飽和したベンチマークや機械翻訳されたタスクを削除し、ネイティブアラビア語の高品質なベンチマーク（Native Arabic MMLU, MedinaQA, AraTrust, ALRAGEなど）を多数追加することで、アラビア語の複雑な言語特性をより正確に捉える評価が可能になりました。

## 重要ポイント
*   **OALL v2のリリース**: アラビア語LLMの評価を強化するため、Open Arabic LLM Leaderboardの第2版が公開されました。
*   **既存課題の解決**: 計算リソースの制約、自己申告制による結果の信頼性不足、機械翻訳されたタスクの不適切さ、飽和したベンチマークといったOALL v1および他のリーダーボードの課題に対応。
*   **ベンチマークの刷新**:
    *   飽和したタスクや機械翻訳されたタスクを削除。
    *   高品質なネイティブアラビア語ベンチマークを多数追加（例: Native Arabic MMLU, MedinaQA, AraTrust, ALRAGE）。
    *   特にALRAGEは、LLM-as-judge評価指標を用いたRAG（Retrieval Augmented Generation）能力を評価する革新的なベンチマークです。
*   **バグ修正と機能改善**: AlGhafaタスクのサイレントバグを修正。UIの改善、チャットテンプレートの導入、モデル提出制限（1組織あたり週5回）を設定。
*   **評価結果の変化**: v2ではモデルランキングに変化が見られ、Llama3.3-70B-instructが多くのカテゴリでトップに立つなど、ネイティブアラビア語ベンチマーク、安全性、信頼性に対するモデルの堅牢性がより明確に評価されるようになりました。

## 詳細レポート（What happened/背景/影響/関係者/データ）
**What happened:**
2025年1月29日、HuggingFaceはOpen Arabic LLM Leaderboard (OALL) の第2版を発表しました。これは、アラビア語LLMの評価における既存の課題を解決し、より包括的で信頼性の高いベンチマークを提供することを目的としています。

**背景:**
アラビア語をサポートするLLMの増加に伴い、専用のリーダーボードの必要性が高まりました。しかし、これまでのリーダーボードには以下の課題がありました。
*   **リソースの制限:** コミュニティメンバーが全てのオープンソースモデルを評価するための計算リソースが不足。
*   **結果の信頼性:** 自己申告制の評価結果の正確性や真正性を保証するメカニズムが不足。
*   **ベンチマークの質:** 既存のベンチマークは、特定の作者による狭い範囲のものや、非アラビア語圏のタスクを機械翻訳したものが多く、アラビア語固有の複雑性（文法、形態論、方言、文化的ニュアンス）を十分に捉えられていませんでした。
*   **飽和したベンチマーク:** OALL v1の一部のベンチマークは、モデルがほぼ完璧なスコアを達成し、モデル間の性能差を識別できなくなっていました。
*   **AlGhafaタスクのバグ:** OALL v1の主要タスクの一つであるAlGhafaに、回答選択肢の検証方法に関するサイレントバグがあり、特に小規模モデルのスコアに不均衡な影響を与えていました。

これらの課題に対処するため、コミュニティからのフィードバックに基づき、より統一され、アクセスしやすく、透明性の高いベンチマークプラットフォームの必要性が強調され、OALL v2の開発に至りました。

**影響:**
*   **評価の精度向上:** ネイティブアラビア語のタスクと高品質なベンチマークの導入により、アラビア語LLMの真の言語理解と生成能力がより正確に評価されるようになりました。
*   **モデルランキングの変化:** 新しいベンチマークと評価方法により、モデルのランキングがOALL v1から変化しました。特にLlama3.3-70B-instructが多くのカテゴリでトップに立ち、Qwenモデルも事前学習モデルカテゴリで優勢を示しています。
*   **コミュニティの活性化:** OALL v1は7ヶ月で46,000以上の訪問者、700以上のモデル提出、180以上の組織からの参加を記録し、アラビア語AIコミュニティの重要なプラットフォームとなりました。v2も同様にコミュニティの参加を促し、アラビア語NLP研究開発を加速させることが期待されます。
*   **公平性の確保:** AlGhafaタスクのバグ修正やモデル提出制限の導入により、評価の公平性と一貫性が向上しました。

**関係者:**
*   **OALL v1ローンチ (2024年5月):** 2A2I, TII, HuggingFace
*   **OALL v2開発チーム:** El Filali, Ali, ALOUI, Manel, Husaain, Tarique, Alzubaidi, Ahmed, Boussaha, Basma El Amel, Cojocaru, Ruxandra, Fourrier, Clémentine, Habib, Nathan, Hacid, Hakim (著者陣)
*   **ベンチマーク提供・協力:**
    *   **MBZUAI:** Native Arabic MMLU, MedinaQA, Human Translated MMLU (MMLU-HT)
    *   **Inception:** Human Translated MMLU (MMLU-HT)
    *   **TII:** 評価バックエンドの推論ハードウェア提供
    *   **Argilla:** ALRAGEデータセットのコミュニティスプリントによる検証
    *   **Hugging Face:** 継続的なサポート

**データ:**
*   **OALL v1の成功:** 7ヶ月で46,000以上の訪問者、過去1ヶ月で2,000以上の訪問、700以上のモデル提出、180以上のユニークな組織からの参加。
*   **モデル分布 (v1):** 提出モデルの70%以上がチャット/ファインチューンモデル、11%が事前学習モデル。50%以上が7Bパラメータ未満。
*   **OALL v2のベンチマーク構成:**

| Datasets kept from OALL v1 | Datasets added for OALL v2 |
| :------------------------- | :------------------------- |
| AlGhafa (6 tasks)          | Native Arabic MMLU (40 tasks) |
| EXAMS                      | Human Translated MMLU (57 tasks) |
| Belebele (2 tasks)         | MedinaQA                   |
|                            | AraTrust                   |
|                            | ALRAGE                     |

*   **ALRAGEベンチマーク:** 40冊のアラビア語書籍から生成されたデータセットを使用し、LLM-as-judge (Qwen2.5-72B-Instruct) メトリックでRAG能力を評価。
*   **モデル提出制限:** 1組織あたり週5回。
*   **結果の比較:**
    *   OALL v2では、ACVAやToxigenのような飽和効果が見られたベンチマークが削除され、AraTrust, ALRAGE, AlGhafa (v2) ではモデルサイズに対する性能の分散がより明確になりました。
    *   他のアラビア語リーダーボード (SEAL Arabic, AraGen) との相関性も確認され、Llama3.3-70B-instructがOALL v2とAraGenで1位、SEALで3位でした。
    *   OALL v2のトップモデルはLlama3.3-70B-instructで、Qwenモデルも事前学習モデルカテゴリで高い性能を示しています。
    *   AceGPTおよびJaisファミリーのモデルでは、一般的に大型モデルほど高スコアの傾向が見られましたが、ALRAGEのような生成タスクでは小規模モデルの性能が低い傾向がありました。

## リスクと課題
*   **既存ベンチマークの限界:** OALL v1や他のリーダーボードが抱えていた、計算リソースの不足、結果の信頼性欠如、機械翻訳されたタスクの不適切さ、飽和したベンチマークといった課題。
*   **アラビア語の複雑性:** 複雑な文法、豊富な形態論、多様な方言、文化的に微妙な安全性の考慮事項など、アラビア語固有の特性を評価に組み込む難しさ。
*   **AlGhafaタスクのバグ:** OALL v1のAlGhafaタスクにおけるサイレントバグが、特に小規模モデルのランキングに不均衡な影響を与えていたこと。
*   **モデル提出制限:** 1組織あたり週5回という提出制限は、一部の組織にとっては評価機会の制約となる可能性があります。
*   **生成タスクの特性:** ALRAGEのような生成タスクは一般的に大規模モデルに有利であり、小規模モデルの評価には課題が残る可能性があります。
*   **今後のベンチマークの多様性:** 数学、推論、幻覚、および汎用・ドメイン固有のベンチマークなど、まだ不足している評価領域が存在します。
