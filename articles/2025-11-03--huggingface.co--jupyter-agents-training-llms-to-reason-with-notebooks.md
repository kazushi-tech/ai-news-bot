## 概要 (TL;DR)

Hugging Faceは、LLMにJupyter Notebookでのコード実行能力を与える「Jupyter Agent」を開発しました。特に小規模モデル（Qwen3-4B）をデータサイエンスエージェントとして強化することを目指し、高品質なトレーニングデータ生成パイプラインと最適化されたスキャフォールディングを構築。その結果、データサイエンスタスク評価ベンチマークであるDABStepにおいて、小規模モデルながらSOTA（State-of-the-Art）性能を達成しました。プロジェクトで生成されたデータセットとファインチューニング済みモデルは公開されています。

## 重要ポイント

*   **Jupyter Agentの目的**: LLMにJupyter Notebook内でコードを実行させ、データ分析・データサイエンスタスクを解決する能力を付与。
*   **小規模モデルの強化**: Qwen3-4Bのような小規模LLMを、データサイエンスエージェントとして大規模モデルに匹敵する性能に向上させることに注力。
*   **DABStepベンチマーク**: Adyenと共同開発した、現実的なデータサイエンスタスクでLLMエージェントの能力を評価するベンチマークを使用。
*   **データ生成パイプライン**: Kaggle Notebooksを基に、大規模な重複排除、データセットダウンロード、教育的スコアリング、フィルタリング、QA生成、トレース生成、最終キュレーションを含む多段階パイプラインで高品質な合成データセットを生成。
*   **スキャフォールディングの最適化**: 約200行に簡素化されたスキャフォールディングと`final_answer`ツールの明示的な追加により、モデル性能が大幅に向上。
*   **顕著な性能向上**: ファインチューニングとスキャフォールディングの組み合わせにより、DABStep Easyスコアでベースラインから最大36%向上し、75%を達成。小規模モデルでSOTAを確立。
*   **リソースの公開**: Jupyter Agent Dataset、ファインチューニング済みQwen3-4Bモデル、および関連コードベースをオープンソースとして公開。

## 詳細レポート

### What happened

Hugging Faceは、LLMがJupyter Notebook環境で直接コードを実行し、データ分析やデータサイエンスのタスクを解決できる「Jupyter Agent」を開発しました。このプロジェクトの主な目的は、特に小規模なLLM（Qwen3-4B）が、大規模モデルに匹敵するデータサイエンスエージェントとしての能力を獲得できるように訓練することでした。
この目標を達成するため、研究チームは以下の主要なステップを実行しました。

1.  **ベンチマークの選定**: データサイエンスエージェントの能力を測定するために、Adyenと共同開発したDABStepベンチマークを採用。
2.  **スキャフォールディングの最適化**: モデルの振る舞いを制御するスキャフォールディングを約200行のコードに簡素化し、`final_answer`ツールを明示的に追加することで、DABStep Easyタスクの精度を44.4%から59.7%に向上させました。
3.  **高品質なトレーニングデータ生成パイプラインの構築**: Kaggle Notebooksを基に、大規模な重複排除、関連データセットのダウンロード、教育的スコアリング、無関係なノートブックのフィルタリング、質問応答（QA）ペアの生成、コード実行トレースの生成、最終的なキュレーションを含む多段階のパイプラインをDatatroveを使用して構築しました。これにより、51,000の合成ノートブックと約0.2Bトークンからなる「Jupyter Agent Dataset」が完成しました。
4.  **モデルのファインチューニング**: 生成されたデータセットを用いてQwen3-4BモデルをTRLでファインチューニング。`assistant_loss_only=True`や`neftune noise`などの技術を適用し、フルパラメータ学習を行いました。

これらの取り組みにより、Qwen3-4BモデルはDABStepベンチマークのEasyタスクで最大75%の精度を達成し、小規模モデルとしてはSOTAの性能を示しました。

### 背景

近年、LLMは複雑でオープンエンドなタスクを解決するために、より多くのツールと自律性を与えられています。その究極のツールとして「コード実行」が挙げられます。Jupyter Notebookは、コードとマークダウンセルで構成され、多段階のコード実行と推論を自然に表示できるため、LLMがデータサイエンスワークフローにネイティブに組み込まれるための理想的な環境です。
既存の大規模LLMは有用な振る舞いを示し始めていますが、小規模モデルはデータサイエンスエージェントタスクにおいて大規模モデルに比べて苦戦しており、その性能向上が課題となっていました。本プロジェクトは、このギャップを埋め、小規模モデルでも強力なエージェントとして機能させることを目指しました。

### 影響

*   **小規模モデルの能力向上**: 本研究は、適切なデータ生成パイプラインとスキャフォールディングを用いることで、Qwen3-4Bのような比較的小規模なLLMでも、データサイエンスエージェントとして大幅な性能向上を達成できることを実証しました。
*   **現実世界タスクへの応用**: 訓練されたモデルは、Kaggleスタイルの現実的なデータ分析タスクを、一貫したコード実行で解決できるようになりました。
*   **コミュニティへの貢献**: 生成された高品質なデータセットとファインチューニング済みモデルが公開されたことで、Jupyter Notebook向けエージェントの開発における新たな研究と実験が促進されることが期待されます。

### 関係者

*   **Hugging Face**: Jupyter Agentプロジェクトの開発と研究を主導。
*   **Adyen**: DABStepベンチマークの共同開発パートナー。
*   **Kaggle**: トレーニングデータ（Kaggle Notebooksおよび関連データセット）の主要な提供元。
*   **Qwen-3 Coder**: ベースモデル（Qwen3-4B-Thinking-2507、Qwen3-4B-Instruct-2507）として、またデータ生成（Qwen3-32B、Qwen-3-Coder-480B-A35B）のLLMとして利用。
*   **E2B**: コード実行サンドボックスとして、トレース生成プロセスで使用。
*   **Datatrove**: 大規模なデータセットパイプラインの構築と管理に使用されたツール。

### データ

*   **DABStep Benchmark**: Adyenと共同で開発された、データサイエンスエージェントの評価ベンチマーク。LLMにデータセットを与え、非自明なデータ質問に回答させるタスクで構成されます。現在のSOTAモデル（Claude 4 Sonnet）でもハードタスクで20%未満の精度しか達成できない、挑戦的なベンチマークです。
*   **Jupyter Agent Dataset**:
    *   **ソースデータ**: 約2TBのKaggle Notebooksと、それにリンクされた約5TBのKaggle Datasets。
    *   **データ生成パイプライン**:
        1.  **大規模な重複排除**: 元のKaggle Notebooksから約90%の重複を排除し、約250GBに削減。
        2.  **リンクされたデータセットのダウンロード**: ノートブックのコード実行を可能にするため、参照される外部データセットを自動的にダウンロード（約5TB）。モデルチェックポイント、大規模なマルチモーダルコーパス、LLM関連ファイル、および10GB以上の非常に大きなデータセットは除外。
        3.  **教育的スコアリング**: Qwen3-32Bを使用してノートブックの教育的品質（明瞭さ、完全性、教育的価値）を1〜5でスコアリングし、約70%の低品質ノートブックをフィルタリング。
        4.  **無関係なノートブックのフィルタリング**: Qwen3-32Bを用いて、LLMトレーニングやデータ分析と無関係なノートブック、およびデータセットを実際に使用していないノートブックを約20%削除。
        5.  **QA生成**: クリーンアップされたノートブックからQwen3-32Bで質問-回答ペアを生成。LLMの幻覚を防ぐため、質問生成と回答検証の2段階プロセスを採用。
        6.  **トレース生成**: Qwen-3-Coder-480Bモデルが、生成された合成QAペアに対するクリーンなJupyter Notebookコード実行トレースを生成。E2Bサンドボックスを使用し、データセットが欠落している場合はLLMをコードインタープリターとしてプロンプト。思考モード非対応モデルには`comment`フィールドを強制することで、推論コメントを生成。
        7.  **最終キュレーション**: 長すぎる出力や自明なトレースを削除し、DABStepスタイルの非自明でマルチターンなトレースのみを保持。
    *   **最終データセット**: 51,000の合成ノートブックと約0.2Bトークンで構成。

### 結果

スキャフォールディングの改善と、上記パイプラインで生成されたデータセットを用いたファインチューニングにより、Qwen3-4BモデルはDABStepベンチマークで大幅な性能向上を達成しました。

| Model | No. of epochs | DABstep (Easy) |
| :-------------------------------- | :------------ | :------------- |
| Qwen-3-4B-Instruct-2507 (Base) | 0 | 38.67% |
| Qwen-3-4B-Instruct-2507 (Our Scaffolding) | 0 | 52.78% |
| Qwen-3-4B-Instruct-2507 | 2 | 63.89% |
| Qwen-3-4B-Instruct-2507 | 3 | 73.61% |
| Qwen-3-4B-Instruct-2507 | 5 | 75% |
| Qwen-3-4B-Instruct-2507 | 7 | 70.83% |

*   ベースモデル（Qwen-3-4B-Instruct-2507）のDABStep Easyスコアは38.67%でした。
*   最適化されたスキャフォールディングを適用することで、スコアは52.78%に向上しました。
*   さらに、合成データセットでファインチューニング（5エポック）を行うことで、スコアは75%に達し、ベースモデルと比較して36%、スキャフォールディング適用モデルと比較して22%の向上を達成しました。
*   ハードタスクのスコアも向上しました。
*   この結果により、Qwen-4B（本パイプラインとスキャフォールディングを適用）はDABStepにおける小規模モデルエージェントのSOTAとなりました。

## リスクと課題

*   **DABStepベンチマークの難易度**: DABStepのハードタスクは非常に難しく、現在のSOTAモデルでも20%未満の精度しか達成できていません。
*   **LLMの幻覚**: QA生成プロセスにおいて、LLMが誤った回答を生成する傾向があり、これを防ぐために質問生成と回答検証の2段階プロセスが必要でした。
*   **データセットの可用性**: トレース生成時にKaggleデータセットが利用できないケースがあり、LLMをコードインタープリターとして機能させることで対応しました。
*   **思考モードの制約**: Qwen3-Coder-480B-A35Bモデルが直接思考モードをサポートせず、コード実行間の推論コメントを生成させるために、ツール呼び出しで`comment`フィールドを必須にする工夫が必要でした。
*   **ツール呼び出しプロンプトの設計**: モデルの性能を最大化するツール呼び出しプロンプトを見つけるのが難しく、手動でのテストが必要でした。また、ツール呼び出しの応答形式に標準化がないため、モデル間の切り替えが困難でした。
*   **TRLのトレーニングモードへの適応**: QwenのネイティブチャットテンプレートがTRLの`assistant_loss_only=True`トレーニングモードに直接適応しておらず、テンプレートの調整が必要でした。
*   **小規模モデルのファインチューニング**: 短い推論テキストでのPEFT（Parameter-Efficient Fine-Tuning）がモデルの能力を損なう可能性があり、このケースではフルパラメータ学習がより良い結果をもたらしました。

*   **より困難なタスクの生成**: 現実世界の分析をよりよく反映する、多段階で挑戦的な質問をさらに生成することを目指します。
*   **規模の拡大**: キュレーションされたトレースの量を増やし、DABStepのハードタスクにおける現在の3.4%という性能をさらに向上させます。
*   **知識蒸留の調査**: 小規模モデルの性能向上に強い結果を示している知識蒸留手法の適用を検討します。
*   **強化学習 (RL) 環境の構築**: 検証可能なQA設定を直接活用し、エージェントタスクでSOTA性能を達成する強化学習環境の構築を計画しています。
*   **コミュニティへの呼びかけ**: 本プロジェクトの成果（Jupyter Agent Dataset、ファインチューニング済みモデル、コードベース）をオープンソースとして公開し、コミュニティがJupyter Notebook向けエージェントの開発を継続することを奨励します。
