## 概要 (TL;DR)
Hugging Faceは、AIモデルの安全性とセキュリティを標準化された方法で評価する新プラットフォーム「RiskRubric.ai」を発表しました。Cloud Security AllianceとNoma Securityが主導し、透明性、信頼性、セキュリティ、プライバシー、安全性、評判の6つの柱でモデルを評価し、0-100点のスコアとA-Fのグレードを提供します。これにより、オープンモデルエコシステムにおける信頼を構築し、開発者がより安全なモデルを選択・改善できるよう支援します。

## 重要ポイント
*   **標準化されたリスク評価**: AIモデルの安全性とセキュリティを6つの柱（透明性、信頼性、セキュリティ、プライバシー、安全性、評判）で一貫して評価する「RiskRubric.ai」が発表されました。
*   **オープンエコシステムの信頼構築**: Hugging Faceハブ上の膨大なモデルの中から、ユーザーがセキュリティ面で最適なモデルを選び、開発者がモデルの弱点を特定し改善するのを支援します。
*   **評価結果の傾向**: 2025年9月時点の評価では、多くのオープンモデルが特定のリスク次元（特に透明性）でクローズドモデルを上回る傾向が見られました。また、モデルのリスク分布は二極化しており、中程度の保護レベルのモデルが懸念領域となっています。
*   **セキュリティと安全性の相関**: コアセキュリティ制御の強化は、有害な出力の防止など、モデルの安全性向上に直接つながることが示されました。
*   **透明性の課題**: 厳格な保護策がユーザーに対する透明性を損なう可能性があり、セキュリティと信頼のバランスが重要です。

## 詳細レポート（What happened/背景/影響/関係者/データ）
### What happened
Hugging Faceは、AIモデルの標準化されたリスク評価プラットフォーム「RiskRubric.ai」の立ち上げを発表しました。これは、AIモデルの安全性とセキュリティに関するレポート作成の迅速な進歩を目指す新しい取り組みです。

### 背景
Hugging Faceハブには50万以上のモデルが存在しますが、ユーザーがセキュリティ面で最適なモデルを選択する方法が不明瞭でした。開発者も、モデルのセキュリティ体制、プライバシーへの影響、潜在的な障害モードを体系的に評価する手段を持っていませんでした。AIモデルの能力向上と普及加速に伴い、AIの安全性とセキュリティ評価の迅速な進歩が喫緊の課題となっています。

### 影響
*   **モデル選択の透明性向上**: 開発者や組織が、特定のニーズ（例：プライバシー重視の医療アプリケーション、一貫性のある出力が求められる顧客向けアプリケーション）に基づいてモデルをフィルタリングし、より適切なデプロイメント決定を下せるようになります。
*   **コミュニティ全体の安全性向上**: リスク評価が公開され標準化されることで、開発者は自身のモデルの強化点を明確に把握し、コミュニティ全体で修正、パッチ、より安全なファインチューニング版の提供を通じてモデルの安全性向上に貢献できます。
*   **オープンモデルエコシステムへの信頼構築**: 厳格で透明性があり、再現性のある評価を通じて、オープンソースモデルへの信頼を高めます。

### データ
#### 評価項目と方法
RiskRubric.aiは、以下の6つの柱でモデルを評価し、0-100点のスコアとA-Fのレターグレードを生成します。各評価には、具体的な脆弱性、推奨される緩和策、改善提案も含まれます。

| 評価の柱 | 評価内容の例 |
| :------- | :----------- |
| **透明性** | ドキュメントの包括的なレビュー（トレーニングデータ、手法など） |
| **信頼性** | 1,000以上の整合性およびエッジケース処理テスト |
| **セキュリティ** | 200以上のジェイルブレイクやプロンプトインジェクションに対する敵対的セキュリティプローブ、モデルコンポーネントの自動コードスキャン |
| **プライバシー** | データ保持および漏洩テストを含むプライバシー評価 |
| **安全性** | 構造化された有害コンテンツテストによる安全性評価 |
| **評判** | （記事に具体的な評価方法は記載なし） |

#### 評価結果の傾向（2025年9月時点）
*   **オープンモデルの優位性**: オープンモデルは、特定の（特に透明性）リスク次元においてクローズドモデルを上回る傾向が見られました。
*   **リスク分布の二極化**:
    *   総リスクスコアは47～94の範囲で、中央値は81点（100点満点）。
    *   モデルの54%がAまたはBレベルの「より安全な」範囲に集中。
    *   しかし、パフォーマンスの低いモデルの長い裾野が平均を押し下げています。
    *   50～67点（C/Dレンジ）のモデルは、全体的な保護レベルが中～低程度であり、セキュリティギャップが実質的な懸念領域となっています。
*   **安全性の「変動要因」**: 安全性・社会性（有害出力防止など）の柱はモデル間で最も大きなばらつきを示しました。セキュリティ強化（プロンプトインジェクション防御、ポリシー適用）に投資したモデルは、安全性スコアも高い傾向にありました。
*   **ガードレールと透明性のトレードオフ**: 厳格な保護策は、説明なしの拒否や隠された境界などにより、エンドユーザーにとってモデルの透明性を低下させる可能性があります。セキュリティと信頼のバランスを取るためには、強力な保護策と説明的な拒否、出所のシグナル、監査可能性を組み合わせることが重要です。

## リスクと課題
*   **中程度の保護レベルのモデル**: 多くのモデルが安全な範囲に集中する一方で、中程度の保護レベル（C/Dレンジ）のモデルが存在し、これらは実質的なセキュリティギャップを持つ懸念領域です。平均的なモデルが安全であると仮定すべきではありません。
*   **透明性の低下**: 厳格なセキュリティ対策（ガードレール）が、ユーザーに対するモデルの透明性を損ない、システムが「不透明」であると認識されることで信頼のギャップを生む可能性があります。

## 今後の見通し/アクション
*   **コミュニティ主導の安全性向上**: 公開され標準化されたリスク評価を通じて、開発者はモデルの強化点を特定し、コミュニティは修正やより安全なファインチューニング版を提供することで、モデルの安全性を継続的に向上させる「好循環」を生み出します。
*   **モデル評価への参加**: ユーザーは自身のモデルを評価のために提出したり、既存のモデルを提案したりして、そのリスクプロファイルを理解することができます。
