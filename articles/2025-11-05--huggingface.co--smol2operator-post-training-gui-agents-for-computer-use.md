## 概要 (TL;DR)

本研究は、軽量なビジョン・言語モデル（VLM）がGUIに根ざしたスキルを習得し、エージェント的なGUIコーダーへと進化するプロセスを実証しました。GUIに特化した基盤能力を持たないSmolVLM2-2.2B-Instructをベースに、2段階のトレーニング戦略と統一されたアクションスペースを用いることで、GUI要素の認識から複雑な推論までを可能にしました。再現性とさらなる研究を促進するため、すべてのトレーニングレシピ、データ処理ツール、結果モデル、デモ、およびデータセットがオープンソースとして公開されています。

## 重要ポイント

*   **GUI自動化のブレークスルー**: GUIに特化した基盤能力を持たない軽量VLM（SmolVLM2-2.2B-Instruct）を、GUIを理解し操作できるエージェント的コーダーに進化させる包括的なトレーニングアプローチを提示。
*   **2段階トレーニング戦略**:
    *   **Phase 1 (Perception)**: GUI要素の認識と位置特定能力を付与。
    *   **Phase 2 (Cognition)**: 行動前の熟考と計画を含むエージェント的な推論能力を強化。
*   **統一されたアクションスペース**: 複数のGUI自動化データセットに存在する異種のアクションフォーマットを、標準化された単一のアクションスペースに変換するデータ変換パイプラインを開発。正規化座標の採用により、解像度に依存しない一貫したデータ処理を実現。
*   **性能の大幅向上**: ScreenSpot-v2ベンチマークで、ベースラインの0%台から最終的に61%超へと大幅な性能向上を達成。
*   **オープンソース化**: トレーニングコード、データ処理ツール、データセット、トレーニング済みモデルを含む全ての成果物をオープンソースとして公開し、GUIエージェント研究の再現性と発展を促進。
*   **最適設定の発見**: 1152pxの画像解像度と0-1範囲の正規化座標がSmolVLM2にとって最適な設定であることを特定。

## 詳細レポート

### What happened/背景

GUI自動化は、コンピュータビジョン分野における最も困難なフロンティアの一つであり、AIエージェントがモバイル、デスクトップ、ウェブプラットフォームを操作できるようにする可能性を秘めています。本研究は、GUIに特化したグラウンディング能力を持たない軽量VLMであるSmolVLM2-2.2B-Instructを、GUIを理解し操作できるエージェント的コーダーへと変革させるための包括的なトレーニングアプローチを提示しました。SOTAモデルの達成ではなく、データ処理からモデルトレーニングまでの全プロセスを実証し、VLMのGUIグラウンディング能力を解放することを目的としています。このアプローチはAGUVIS論文に触発され、そのキュレーションされたデータセットを活用しています。

### 影響

本研究は、高品質で推論指向のデータが、小規模なVLMであってもGUIグラウンディング能力を大幅に向上させることを実証しました。SmolVLM2-2.2B-Instructは、ScreenSpot-v2ベンチマークで初期性能0%台から61.71%へと劇的に改善しました。また、トレーニングレシピ、データ処理ツール、モデル、データセットのオープンソース化により、GUIエージェント研究コミュニティがこれらの成果を基に、さらなる研究や応用を進めるための基盤を提供しました。

### データ

**データ変換と統一アクションスペース**

*   **課題**: 複数のGUI自動化データセットは、アクション表現（関数名、パラメータ、分類法）に一貫性がなく、統一モデルのトレーニングを困難にしていました。
*   **アプローチ**: AGUVISのオープンソースデータセット（xlangai/aguvis-stage1, xlangai/aguvis-stage2）に対し、以下のデータ変換パイプラインを適用しました。
    *   **関数解析と正規化**: 多様なフォーマットの関数呼び出しを解析し、適切なパラメータ順序で再構築。
    *   **アクションスペースの統一**: 元のアクション表現を標準化された関数名と引数構造に変換。不要なアクションの削除、パラメータ命名規則の標準化、一貫したアクション語彙の作成を実施。
    *   **正規化座標の採用**: ピクセル座標は画像サイズに依存するため、モデルのリサイズ時に問題が生じます。0-1範囲の正規化座標を使用することで、任意の解像度で有効性を保ち、データセットの一貫性を維持しました。
*   **Action Space Converter**: ユーザーが独自のカスタムアクション語彙や命名規則にデータセットを適応させるための柔軟なツールも開発されました。

**データ変換例**

| 変換前 (オリジナルアクション)                               | 変換後 (統一アクション)                               |
| :------------------------------------------------------ | :---------------------------------------------------- |
| `mobile.home()`                                         | `navigate_home()`                                     |
| `mobile.open_app(app_name='drupe')`                     | `open_app(app_name='drupe')`                          |
| `pyautogui.click(x=0.8102, y=0.9463)`                   | `click(x=0.8102, y=0.9463)`                           |
| `pyautogui.hotkey(keys=['ctrl', 'c'])`                  | `press(keys=['ctrl', 'c'])`                           |
| `pyautogui.write(message='bread buns')`                 | `type(text='bread buns')`                             |
| `pyautogui.scroll(page=-0.1)`                           | `scroll(direction='up', amount=10)`                   |
| `assistant_message: "Action: click(x=0.5, y=0.3)"`      | `assistant_message: "Action: touch(x_coord=200, y_coord=300)"` (カスタム変換例) |

**変換・公開されたデータセット**

*   `smolagents/aguvis-stage-1`
*   `smolagents/aguvis-stage-2`

### 学習プロセス

**Phase 1: From Zero to Perception**

*   **目的**: モデルにGUIグラウンディング能力（GUI要素の認識と位置特定）を付与。
*   **トレーニングデータ**: `smolagents/aguvis-stage-1`を使用。低レベルの指示と実行可能なアクション（コード形式）をペアリング。
*   **最適化実験**: 画像サイズ（384px, 768px, 1152px）と座標システム（ピクセル座標 vs. 正規化座標）を比較。
*   **主要な発見**: 1152pxの画像サイズと0-1範囲の正規化座標がSmolVLM2に最も効果的。
*   **結果**: ScreenSpot-v2ベンチマークで、ベースラインの0.47%（正規化座標）から41.27%へと大幅に改善。

**Phase 2: From Perception to Cognition**

*   **目的**: モデルのエージェント的な推論能力（行動前の熟考と計画）を強化。
*   **トレーニングデータ**: `smolagents/aguvis-stage-2`を使用。明示的な推論と複数ステップのインタラクションを含むシナリオを導入。
*   **結果**: Phase 1のチェックポイントからさらにScreenSpot-v2ベンチマークで41.27%から61.71%へと改善。これは、明示的な推論がGUIグラウンディング性能を向上させることを示しています。
*   **補足**: より小さなVLM（nanoVLM-460M）でも約58%を達成し、このトレーニング戦略がモデルサイズに関わらず効果的であることを実証。

## リスクと課題

*   現在の教師ありファインチューニング（SFT）ベースのアプローチは、静的データセットに依存しており、リアルタイムの適応や、より複雑で動的なGUI環境における高度な推論能力の獲得には限界があります。
*   本研究はSOTAモデルの達成を主目的としていないため、絶対的な性能では他の大規模なGUIエージェントモデルに劣る可能性があります。
*   異なるベースモデルや、多様なGUIプラットフォーム（例：特定のOSやアプリケーション）への汎用性については、さらなる検証と適応が必要となる可能性があります。
