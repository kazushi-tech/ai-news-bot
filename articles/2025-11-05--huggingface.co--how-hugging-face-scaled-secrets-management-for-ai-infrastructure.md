## 概要 (TL;DR)
Hugging Faceは、AIインフラのシークレット管理をHashiCorp Vaultなどの既存ソリューションではなく、Infisicalに移行しました。この移行により、マルチクラウド・Kubernetes環境におけるシークレットスプロール、複雑な権限管理、ローカル開発の非効率性といった課題を解決。InfisicalのKubernetes Operator、CLI、Okta連携によるRBAC強化を通じて、セキュリティ体制を大幅に向上させるとともに、エンジニアリング時間の節約と開発効率の向上を実現しました。

## 重要ポイント
*   **背景と課題**: Hugging FaceのインフラがAWS単一からマルチクラウド（Azure, GCP）へ拡大し、400万人以上のビルダーを抱える中で、シークレットスプロール、複雑な権限管理、ローカル開発の非効率性、手動シークレットローテーションの負担が深刻化。過去のセキュリティインシデントも背景に。
*   **ソリューション選択**: 開発者フレンドリーなワークフロー、マルチクラウド抽象化、堅牢なセキュリティ機能を評価し、HashiCorp VaultではなくInfisicalを採用。
*   **主要な導入効果**:
    *   **Kubernetes連携**: Infisical Operatorによるシークレットの自動同期とコンテナリロード（ただし、Hugging Faceは手動デプロイを優先）。
    *   **ローカル開発**: Infisical CLIによるセキュアなシークレット注入で、.envファイルの利用を廃止。
    *   **セキュリティ強化**: Okta連携によるきめ細やかなRBAC、自動監査、セキュアな資格情報共有。
    *   **CI/CD統合**: GitHub Actions、OIDC認証、Terraform連携によるセキュアなデプロイメント。
*   **成果**: エンジニアリング時間の節約、セキュリティ体制の「シフトレフト」アプローチ、インフラ全体での一貫したシークレット管理を実現。

## 詳細レポート（What happened/背景/影響/関係者/データ）

**What happened:**
Hugging Faceは、AIインフラにおける機密性の高い設定データ（シークレット）の管理方法を刷新するため、Infisicalを導入し、既存のシークレット管理システムからInfisicalへの移行を完了しました。

**背景:**
*   **インフラの進化**: AWS単一環境からAzure、GCPを含むマルチクラウド環境へと拡大。
*   **プラットフォームの成長**: 400万人以上のビルダーがHugging Face Hubにモデルをデプロイする規模に成長。
*   **既存の課題**:
    *   **シークレットスプロール**: 環境間での管理の一貫性がなく、リスクが増大。
    *   **複雑な権限管理**: チーム規模の拡大に伴い、組織のSSO（Okta）と統合されたロールベースアクセス制御（RBAC）が必須。
    *   **ローカル開発の非効率性**: 従来の.envファイルがセキュリティと開発者生産性の両方を損なっていた。
    *   **手動ローテーションの負担**: 資格情報漏洩を伴うセキュリティインシデント後、手動でのシークレットローテーションの負担が顕著に。
*   **要件**: Infrastructure-as-Codeの原則への準拠、プロジェクトごとのシークレット管理、デプロイ時の自動化と手動制御のバランス。

**影響:**
*   **実装とKubernetes連携**:
    *   Infisicalの柔軟なアーキテクチャを活用し、プロジェクト構造をインフラとアプリケーションドメインに分割。
    *   TerraformとInfisical Kubernetes Operatorを統合し、Kubernetes環境でのシークレット管理を標準化。
    *   OperatorはInfisicalのシークレット変更を監視し、Kubernetesオブジェクトに自動同期。変更時には依存するDeploymentの自動リロードも可能（Hugging Faceは高トラフィック環境での精密な制御のため、手動デプロイを優先）。
*   **ローカル開発**: Infisical CLIが開発環境にシークレットを直接注入することで、セキュアでない.envファイルの利用を排除し、オンボーディングと開発効率を向上。
*   **セキュリティとアクセス管理**:
    *   OktaとInfisicalを統合し、きめ細やかなRBACシステムを確立。Oktaグループから権限が自動マッピングされ、適切なアクセス制御を実現。
    *   集中管理されたInfisicalプラットフォームにより、監査とシークレットローテーションの管理が簡素化。
    *   ML/AI研究者間でのセキュアな資格情報共有が可能に。
*   **CI/CDとインフラ統合**: GitHub Actions、OIDC認証、Terraformを介してInfisicalをCI/CDパイプラインに組み込み、セキュアなデプロイメントを実現。

**関係者:**
*   Hugging Face (エンジニアリングチーム、インフラ責任者 Adrien Carreira)
*   Infisical (シークレット管理ソリューション提供元)

**データ:**

## リスクと課題
*   **移行前の課題**:
    *   マルチクラウド環境でのシークレットスプロールと管理の一貫性の欠如。
    *   チーム規模拡大に伴う複雑な権限管理とSSO連携の必要性。
    *   ローカル開発における.envファイルのセキュリティリスクと生産性の低下。
    *   過去のセキュリティインシデントにより露呈した手動シークレットローテーションの負担。
*   **移行後の潜在的課題**:
    *   記事中には明示的なリスクや課題は記述されていませんが、新しいツールへの依存、Infisical自体のセキュリティ脆弱性、Operatorの自動リロード機能を手動デプロイに切り替えることによる運用上の考慮事項などが挙げられます。

## 今後の見通し/アクション
*   Hugging FaceのInfisicalへの移行は、セキュリティと開発効率の両面で大きな成功を収めました。
*   「セキュアなパスを最も簡単なパスにする」というアプローチにより、エンジニアリングチームはシークレット管理の懸念から解放され、イノベーションに集中できるようになります。
*   同様の課題を抱えるチームに対して、Infisicalの導入が効率的かつセキュアなシークレット管理を実現する実用的な方法として推奨されています。
