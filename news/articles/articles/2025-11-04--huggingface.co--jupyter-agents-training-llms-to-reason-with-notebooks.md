## 概要 (TL;DR)
Hugging Faceは、LLMにJupyter Notebook内でのコード実行能力を与え、データサイエンスタスクを解決する「Jupyter Agent v2」を発表しました。本プロジェクトでは、特にQwen-3-4Bのような小規模モデルの性能向上に焦点を当て、高品質な合成訓練データ生成パイプラインと最適化されたスキャフォールディングを開発。これにより、DABStepベンチマークのEasyタスクで75%の精度を達成し、小規模モデルとしてはSOTA（State-of-the-Art）の性能を示しました。訓練済みモデルとデータセットはオープンソースとして公開されています。

## 重要ポイント
*   **Jupyter Agent v2**: LLMがJupyter Notebook環境でコードを実行し、データ分析・データサイエンスタスクを解決するためのエージェント。
*   **小規模モデルの強化**: Qwen-3-4Bのような小規模LLMを対象に、データサイエンスエージェントとしての性能向上を目指した。
*   **DABStepベンチマーク**: データサイエンスエージェントの評価に用いられる現実的なタスクベンチマーク。現状のLLMには依然として困難な課題が多い。
*   **高品質データ生成パイプライン**: Kaggleノートブックを基に、大規模な重複排除、関連データセットのダウンロード、教育的スコアリング、無関係なノートブックのフィルタリング、QAペア生成、コード実行トレース生成、最終キュレーションを行う多段階パイプラインを構築。
*   **スキャフォールディングの最適化**: 約200行の簡素化されたスキャフォールディング（`final_answer`ツールを含む）を開発し、モデルの性能を大幅に向上させた。
*   **訓練成果**: Qwen-3-4Bを合成データセットでファインチューニングした結果、DABStep (Easy) で最大75%の精度を達成。これはベースモデルやスキャフォールディングのみの場合と比較して大幅な向上であり、小規模モデルとしてはSOTA。
*   **オープンリリース**: 訓練済みモデル（Jupyter-Agent-Qwen3-4B-Instruct/Thinking）と訓練データセット（Jupyter Agent Dataset）を公開し、コミュニティでの利用と研究を促進。

## 詳細レポート
### What happened
Hugging Faceは、LLMがJupyter Notebook環境でコードを実行し、データ分析・データサイエンスタスクを解決する「Jupyter Agent」の第2版を開発しました。特に、Qwen-3-4Bのような小規模モデルが、大規模モデルに匹敵するエージェント性能を発揮できるよう、高品質な訓練データ生成パイプラインと最適化されたスキャフォールディングを構築し、ファインチューニングを実施。その結果、DABStepベンチマークのEasyタスクで75%の精度を達成し、小規模モデルとしてはSOTAの性能を示しました。

### 背景
近年、LLMにツールと自律性を与え、より複雑でオープンエンドなタスクを解決する動きが活発です。その中で、コード実行はLLMにとって究極のツールと位置づけられています。Jupyter Notebookは、コード実行と推論を多段階で表示する自然な形式であるため、この環境で動作するエージェントの開発が進められました。しかし、既存の小規模モデルは、エージェント的なデータサイエンスタスクにおいて大規模モデルに比べて性能が劣るという課題がありました。本プロジェクトは、このギャップを埋めることを目的としています。

### 影響
*   **小規模モデルの能力向上**: Qwen-3-4Bのような比較的小規模なモデルでも、適切な訓練データとスキャフォールディングを組み合わせることで、強力なデータサイエンスエージェントとして機能することを実証しました。
*   **データサイエンスワークフローへの統合**: Jupyter Agentは、Cursorのようにデータサイエンスワークフローにネイティブに組み込まれることで、データ分析の効率化に貢献する可能性を秘めています。
*   **ベンチマーク性能の向上**: DABStepベンチマークのEasyタスクで75%の精度を達成し、小規模モデルの新たなSOTAを確立しました。
*   **研究コミュニティへの貢献**: 訓練済みモデルとデータセットが公開されたことで、Jupyter Notebook向けエージェントの研究開発がさらに加速することが期待されます。

### 関係者
*   **Hugging Face**: Jupyter Agent v2の開発、データセットとモデルの公開を主導。
*   **Adyen**: データサイエンスエージェント評価ベンチマーク「DABStep」の共同開発パートナー。
*   **Kaggle**: 訓練データ生成の基盤となるノートブックとデータセットを提供。
*   **Qwen**: ベースモデルとしてQwen3-4B-Thinking-2507、Qwen3-32B、Qwen-3-Coder-480B-A35Bが使用された。
*   **E2B**: コード実行サンドボックスとして利用され、トレース生成に貢献。
*   **Datatrove**: 大規模なデータパイプライン構築に利用されたツール。

### データ
訓練データは、主にKaggleのノートブックとデータセットを基に、以下の多段階パイプラインで生成されました。
1.  **大規模重複排除**: 約2TBのKaggleノートブックから約90%の重複を排除し、約250GBに削減。
2.  **リンクされたデータセットのダウンロード**: ノートブックが参照する約5TBのKaggleデータセットをダウンロード。モデルチェックポイント、大規模マルチモーダルコーパス、LLM関連ファイル、10GB以上のデータセットは除外。
3.  **教育的スコアリング**: Qwen3-32Bを用いてノートブックの教育的品質を1-5点で評価し、約70%の低品質ノートブックをフィルタリング。
4.  **無関係なノートブックのフィルタリング**: LLM訓練やデータ分析と無関係なノートブック、データセットを実際に使用しないノートブックを約20%フィルタリング。
5.  **QA生成**: Qwen3-32Bを用いて、クリーンなノートブックから質問-回答ペアを生成。LLMの幻覚を防ぐため、質問生成と回答検証の2段階プロセスを採用。
6.  **トレース生成**: Qwen-3-Coder-480BモデルとE2Bサンドボックスを使用し、生成されたQAペアに対するクリーンなJupyter Notebookコード実行トレースを生成。データセット欠損時にはLLMをコードインタープリタとして活用し、思考モード非対応モデルにはコメント強制の工夫を適用。
7.  **最終キュレーション**: 長すぎる出力や自明なトレースを削除し、DABStepスタイルのタスクに合わせた非自明で多段階のトレースのみを保持。

最終的に生成された「Jupyter Agent Dataset」は、51,000の合成ノートブックと約0.2Bトークンで構成されています。

### 訓練結果
初期のQwen3-4B-Thinking-2507モデルのベースライン性能は、Easyタスクで44.4%、Hardタスクで2.1%でした。
簡素化されたスキャフォールディングを適用することで、Easyタスクの精度は44.4%から59.7%に向上しました。
ファインチューニングによるDABStep (Easy) タスクの精度変化は以下の通りです。

| Model                        | No. of epochs | DABstep (Easy) |
| :--------------------------- | :------------ | :------------- |
| Qwen-3-4B-Instruct-2507 (Base) | 0             | 38.67%         |
| Qwen-3-4B-Instruct-2507 (Our Scaffolding) | 0             | 52.78%         |
| Qwen-3-4B-Instruct-2507      | 2             | 63.89%         |
| Qwen-3-4B-Instruct-2507      | 3             | 73.61%         |
| Qwen-3-4B-Instruct-2507      | 5             | 75%            |
| Qwen-3-4B-Instruct-2507      | 7             | 70.83%         |

この結果から、スキャフォールディングとファインチューニングの両方が性能向上に大きく貢献していることがわかります。特に、5エポックの訓練で75%の精度を達成し、ベースモデルと比較して最大36%、スキャフォールディング適用モデルと比較して22%の向上が見られました。Hardタスクの精度も向上しましたが、Easyタスクほど顕著ではありません。

## リスクと課題
*   **DABStepベンチマークの難易度**: DABStepのHardタスクは、現在の最先端LLM（例: Claude 4 Sonnet）でも20%未満の精度しか達成できず、依然として大きな課題。
*   **LLMの幻覚**: QA生成プロセスにおいて、LLMが誤った回答を生成する傾向があり、これを防ぐために2段階の検証プロセスが必要だった。
*   **データセットの可用性**: トレース生成時に多くのKaggleデータセットが利用できない場合があり、LLMをコードインタープリタとして機能させる工夫が必要だった。
*   **LLMの思考モードの制約**: Qwen3-Coder-480B-A35Bのようなモデルは思考モードを直接サポートせず、コードコメントを強制的に生成させるためのツール呼び出しの工夫が必要だった。
*   **ツール呼び出しのプロンプト設計の複雑さ**: モデルのツール呼び出し性能はプロンプト設計に大きく依存し、最適なプロンプトを見つけるために手動テストが必要。
*   **ツール呼び出し応答形式の標準化不足**: モデル間でツール呼び出しの応答形式に一貫性がなく、モデルの切り替えが困難。
*   **TRLの訓練モードへの適応**: TRLの`assistant_loss_only=True`モードにQwenのチャットテンプレートを適応させるための調整が必要だった。
*   **思考モデルの訓練における課題**: 短い推論テキストでの訓練がモデル能力を損なう可能性があり、このケースではPEFTよりもフルパラメータ訓練が有効だった。
*   **Hardタスクの性能向上**: 現在のパイプラインではHardタスクでの性能向上が限定的であり、さらなる改善が必要。

## 今後の見通し/アクション
*   **より困難なタスクの生成**: 現実世界の複雑な分析をよりよく反映する、より挑戦的で多段階の質問を生成し、ベンチマークの難易度を上げる。
*   **スケーリング**: より大量のキュレーションされたトレースで訓練することで、Hardタスクの現在の3.4%の性能をさらに向上させる。
*   **知識蒸留 (Distillation)**: 小規模モデルの性能向上に有効な知識蒸留技術を調査し、適用する。
*   **強化学習 (RL)**: 検証可能なQAセットアップを直接活用し、エージェントタスクで最先端の性能を達成している強化学習環境を構築する。
*   **コミュニティとの連携**: Jupyter Agent Datasetとコードベースを公開し、コミュニティがJupyter Notebook向けエージェントの開発を継続することを奨励し、協力してさらなる進歩を目指す。
